Wazuh + OpenCTI — Real-Time Enrichment & Alerting Architecture

Endpoint telemetry is decoded by Wazuh, selected alerts are enriched live through OpenCTI's GraphQL API, eligible direct indicator matches can create a STIX sighting, and the enriched event is re-injected for rule evaluation, dashboard visibility and optional Telegram notification.

1

Telemetry collection

Windows and Linux agents forward endpoint events. Optional IDS/Packetbeat, osquery, and network alerts require collection and routing to be configured.

2

Decode and select

analysisd applies decoders and rules; alerts matching configured groups are handed to integratord.

3

Integration trigger

integratord dispatches the selected alert JSON to custom-opencti.py.

4

Live GraphQL lookup

The hook extracts IOCs and queries OpenCTI in real time, with no local IOC files to sync.

5

Sighting write-back

Eligible direct indicator matches create a STIX sighting in OpenCTI; filename and related-indicator matches do not. The state file prevents duplicates.

6

Context returned

Indicator and observable results flow back to the hook and are merged with the original alert.

7

Re-injection

The enriched event is pushed through a local socket/queue and re-processed as an agent-attributed event.

8

Rules and visibility

Rules 100210–100222 are loaded into analysisd; resulting alerts reach the dashboard and standard indexer output.

9

Optional Telegram alert

opencti_alert / opencti_high groups at level 10+ trigger custom-telegram.py to message the SOC chat through the Bot API.

Closed-loop automation: detection → intelligence enrichment → sighting evidence → re-evaluation. Prepared by Abu Saeid
